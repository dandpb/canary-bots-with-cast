# Task Scheduling & Save Management (`src/game/scheduling`)

## Overview
Provides the central asynchronous task loop (`Dispatcher` and `Task`), weighted deficit round-robin lane scheduling and adaptive load budgets (`DispatcherWeightedDeficitRoundRobin`, `DispatcherAdaptiveBudgetController`, `MonsterComputeService`), calendar-driven event rate scheduling (`EventsScheduler`), and durable persistence orchestration (`SaveManager` and `SerialSaveQueue`) for players, bots, guilds, map state, and the key-value store.

## Interface
- `Dispatcher` / `g_dispatcher`, `DispatcherContext`, `TaskGroup`, `DispatcherType`, `DispatcherInternalWork`, `CreatureAsyncSliceLimits` (`[dispatcher.hpp:Dispatcher]`, `[dispatcher.hpp:g_dispatcher]`, `[dispatcher.hpp:DispatcherContext]`, `[dispatcher.hpp:TaskGroup]`, `[dispatcher.hpp:DispatcherType]`): Main game event loop and parallel task coordinator (`addEvent`, `addWalkEvent`, `cycleEvent`, `scheduleEvent`, `asyncEvent`, `asyncWait`, `asyncCycleEvent`, `asyncScheduleEvent`, `safeCall`, `stopEvent`, `isOnDispatcherThread`, `isShuttingDown`, `DISPATCHER_LANE_QUEUE_CAPACITY = 16384`).
- `DispatcherLane`, `ExecutionMode`, `TaskMeta`, `defaultExecutionMode`, `isMovementCommit` (`[dispatcher_types.hpp:DispatcherLane]`, `[dispatcher_types.hpp:TaskMeta]`): Lane taxonomy (`ProtocolInput`, `PlayerWalk`, `PlayerAction`, `WorldCommit`, `WorkerCompletion`, `VisibleMonster`, `BackgroundMonster`, `VisibleMonsterAI`, `MonsterAI`, `Deferred`, `Maintenance`, `GenericParallel`), execution modes, and task cost ceiling (`DISPATCHER_MAX_TASK_COST = 32`).
- `DispatcherQueueSnapshot`, `DispatcherAdmissionResult`, `DispatcherAdmissionCounter` (`[dispatcher_policy.hpp:DispatcherQueueSnapshot]`, `[dispatcher_policy.hpp:DispatcherAdmissionCounter]`): Bounded queue admission and snapshot tracking (`dispatcher_policy.hpp`).
- `DispatcherWeightedDeficitRoundRobin` (`[dispatcher_wdrr.hpp:DispatcherWeightedDeficitRoundRobin]`, `[dispatcher_wdrr.cpp:DispatcherWeightedDeficitRoundRobin::selectLane]`): Fair deficit round-robin scheduler across `DispatcherLane`s with SLO age scaling (`agedQuantum`).
- `DispatcherLoadState`, `DispatcherBudgetSet`, `DispatcherBudgetDecision`, `DispatcherAdaptiveBudgetController` (`[dispatcher_budget.hpp:DispatcherAdaptiveBudgetController]`, `[dispatcher_budget.cpp:DispatcherAdaptiveBudgetController::update]`): Adapts per-tick walk/async/deferred/completion budgets across `Normal`, `Constrained`, and `Emergency` load states.
- `dispatcher::telemetry::LatencySnapshot`, `LATENCY_BUCKET_UPPER_BOUNDS_US` (`[dispatcher_telemetry.hpp:dispatcher::telemetry::LatencySnapshot]`): Histogram latency bucket collector and percentile evaluator.
- `MonsterComputeService`, `MonsterComputeToken`, `MonsterComputePriority`, `MonsterComputeSubmitStatus`, `MonsterComputeSubmission`, `MonsterComputeConfig`, `MonsterComputeStats` (`[monster_compute_service.hpp:MonsterComputeService]`, `[monster_compute_service.cpp:MonsterComputeService::submit]`): Dedicated cancellable background compute queue (`submit`, `drainCompletions`, `start`, `shutdown`) returning dispatcher completions.
- `Task` (`[task.hpp:Task]`): Callable unit of work with expiration, delay, cycle flag, and monotonic event ID (`getId`, `getDelay`, `getContext`, `getTime`, `hasExpired`, `isCycle`, `isCanceled`, `cancel`, `execute`).
- `EventsScheduler` / `g_eventsScheduler`, `EventScheduler`, `EventRates` (`[events_scheduler.hpp:EventsScheduler]`, `[events_scheduler.hpp:g_eventsScheduler]`, `[events_scheduler.hpp:EventScheduler]`, `[events_scheduler.hpp:EventRates]`): JSON/XML calendar event loader and rate multiplier manager (`loadScheduleEventFromJson`, `loadScheduleEventFromXml`, `getExpSchedule`, `getLootSchedule`, `getBossLootSchedule`, `getSpawnMonsterSchedule`, `getSkillSchedule`, `getActiveEvents`, `reset`).
- `SaveManager` / `g_saveManager`, `SaveManager::PlayerSave` (`[save_manager.hpp:SaveManager]`, `[save_manager.hpp:g_saveManager]`): Coordinates full server saves, shutdown final-save freezing/retries, and individual player/logout/bot/guild saves (`saveAll`, `beginFinalSave`, `saveFinal`, `finalCommitUncertain`, `scheduleAll`, `savePlayer`, `saveLogoutPlayer`, `hasPendingLogout`, `saveBotPosition`, `getPendingBotPlayer`, `bool saveGuild`, `bool saveBatch`, `bool saveMap`, `bool saveKV`).
- `SerialSaveQueue<Value>` (`[serial_save_queue.hpp:SerialSaveQueue]`): Thread-safe, generation-tracked per-GUID save coalescing queue (`request`, `take`, `finish`, `find`, `snapshot`).

## Invariants
- `Dispatcher` pre-allocates `threadPool.get_thread_count() + 4` `ThreadTask` slots so every thread calling `ThreadPool::getThreadId()` (pool workers, main/asio thread, `BotDatabaseTasks` worker) indexes `threads` in-bounds without locking a global queue (`[dispatcher.hpp:Dispatcher::Dispatcher]`, `[dispatcher.hpp:Dispatcher::getThreadTask]`).
- Once `Dispatcher::shutdown()` sets `shuttingDown = true`, all new enqueue calls (`addEvent`, `addWalkEvent`, `scheduleEvent`, `asyncEvent`) are dropped and `executeScheduledEvents()` immediately returns so `[this]`-capturing lambdas cannot fire on destroyed map/spawn objects (`[dispatcher.hpp:Dispatcher::shutdown]`, `[dispatcher.cpp:Dispatcher::executeScheduledEvents]`).
- `Dispatcher::asyncWait` sets `asyncWaitDisabled = true` while a parallel partition is active to prevent nested `asyncWait` fork-join deadlocks (`[dispatcher.cpp:Dispatcher::asyncWait]`).
- `Task` constructors assert that `context` is non-empty (`!this->context.empty()`), and `Task::getId()` generates non-zero monotonic IDs skipping `0` on wrap-around (`[task.hpp:Task::getId]`, `[task.cpp:Task::Task]`).
- `SerialSaveQueue::finish` compares the completed `generation` against `entry.generation`: if a newer generation was requested while the worker was running, it returns `true` so the worker immediately persists the newer state, and on failure (`success == false`) retains the entry in `entries_` (`[serial_save_queue.hpp:SerialSaveQueue::finish]`).
- `SaveManager::enqueuePlayerSave` captures `PlayerSaveSnapshot` on the dispatcher before handing SQL to `playerSavePool_`. Human logout snapshots stay queued until saved. Final snapshots are captured after logout callbacks, and shared shutdown stages wait for all character saves to succeed (`[save_manager.cpp:SaveManager::enqueuePlayerSave]`, `[save_manager.cpp:SaveManager::saveFinal]`).
- `SaveManager::beginFinalSave` stops ordinary save scheduling. A failed or unconfirmed final write keeps shutdown pending (`[save_manager.cpp:SaveManager::beginFinalSave]`, `[save_manager.cpp:SaveManager::saveFinal]`).

## Side Effects
- Spawns the detached main dispatcher loop on `threadPool`, updates `OTSYS_TIME()` each cycle, drains `DbDispatcherStats::fetchResetSyncDbUs()`, and logs jitter telemetry (`[CYCLE_SLOW]`, `[CYCLE_GAP]`, `[DISP_SLOW]`, `[ASYNC_WAIT]`, `[DISP_RATES]`) (`[dispatcher.cpp:Dispatcher::init]`, `[dispatcher.cpp:Dispatcher::executeSerialEvents]`, `[dispatcher.cpp:Dispatcher::executeScheduledEvents]`).
- `SaveManager::runPlayerSave` uses thread-local database connections and posts checkpoint acknowledgements to the dispatcher. Logout saves and shutdown stages use receipts in `server_config` (prepared via `DBTransaction::prepareReceipt` in `src/database/database.cpp`) to confirm a prior commit before replaying writes (`[save_manager.cpp:SaveManager::runPlayerSave]`).
- `SaveManager` persists players, guilds, map state (`Map::save`), and key-value entries (`kv.saveAll()`) (`[save_manager.cpp:SaveManager::saveBatch]`, `[save_manager.cpp:SaveManager::doSavePlayer]`).
- `EventsScheduler` reads `events.json` / `events.xml`, loads event Lua scripts via `g_scripts().loadEventSchedulerScripts`, mutates global schedule rate multipliers and `g_kv().scoped("eventscheduler")` keys (`forge-chance`, `double-bestiary`, `double-bosstiary`, `fast-exercise`, `boss-cooldown`), and calls `consoleHandlerExit()` on missing/corrupt schedule files (`[events_scheduler.cpp:EventsScheduler::loadScheduleEventFromJson]`, `[events_scheduler.cpp:EventsScheduler::loadScheduleEventFromXml]`).
