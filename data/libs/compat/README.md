# Legacy Compatibility Layer (`data/libs/compat`)

## Overview

Provides backward-compatible global functions, constants, and table wrappers (`compat.lua`) bridging legacy OpenTibia/TFS procedural Lua APIs (`doPlayer*`, `getCreature*`, `getTile*`, `result.*`, `Combat`, `Condition`) to Canary's object-oriented Lua metatables (`Player`, `Creature`, `Monster`, `Npc`, `Item`, `ItemType`, `Tile`, `House`, `Town`, `Guild`, `Combat`, `Condition`, `Game`).

## Invariants

- `[compat.lua:getThing]`, `[compat.lua:doTeleportThing]`, `[compat.lua:getThingPos]`: Numeric UIDs `>= 0x10000000` resolve as `Creature(uid)`, whereas numeric UIDs `< 0x10000000` resolve as `Item(uid)`.
- `[compat.lua:pushThing]`: Always returns a table `{ uid = 0, itemid = 0, type = 0, actionid = 0 }`, setting `itemid = 1` and `uid = thing:getId()` when `thing` is a `Creature`.
- `[compat.lua:getConfigInfo]`: Returns `nil` if `type(info) ~= "string"`.
- `[compat.lua:getGlobalStorageValue]`: Returns `-1` when `Game.getStorageValue(key)` is `nil` or `false`.
- `[compat.lua:doCreateTeleport]`: Removes the created item and returns `false` if `not item:isTeleport()`.
- `[compat.lua:doSetMonsterTarget]`, `[compat.lua:doMonsterChangeTarget]`: Returns `true` without changing target if `monster:getMaster()` is non-nil (summons).

## Side Effects

- `[compat.lua:getConfigInfo]`: Executes `dofile("config.lua")` and reads `_G[info]`.
- `[compat.lua:getPlayerGUIDByName]`, `[compat.lua:getGuildId]`: Executes synchronous SQL queries against `players` and `guilds` tables via `db.storeQuery`.
- `[compat.lua:Combat.setCondition]`, `[compat.lua:doCombat]`: Emits deprecation warnings via `logger.warn`.
- Mutates world state (spawning/removing items, monsters, NPCs, teleports, conditions, outfits, guild memberships, house ownership, and player/global storages) via `Game`, `Player`, `Creature`, `Tile`, and `House` metatables.
